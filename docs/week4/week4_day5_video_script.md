# Сценарий видео — День 20: Оркестрация MCP (week4/day5)

Немой скринкаст консоли. Без озвучки. Формат: что печатаю → что получаю.
Один запуск: поднимаются 3 MCP-сервера, агент через DeepSeek сам выбирает инструменты
с разных серверов и выполняет длинный флоу.

---

## ШАГ 1 — запуск

Печатаю (Windows PowerShell; chcp 65001 — чтобы кириллица читалась):
```
chcp 65001
.\gradlew.bat :week4:day5:run --console=plain -q
```
(на Linux/Mac: `./gradlew :week4:day5:run --console=plain -q`)

Получаю:
```
Подняты 3 MCP-сервера: knowledge:3010, weather:3011, files:3012
  сервер «knowledge» (порт 3010): search, summarize
  сервер «weather» (порт 3011): get_weather
  сервер «files» (порт 3012): save_to_file
Общий реестр (4): knowledge__search, knowledge__summarize, weather__get_weather, files__save_to_file

=== ЦЕЛЬ: Узнай погоду в Novosibirsk и справку о Новосибирске, сделай сводку и сохрани в файл ===
[шаг 1 · роутинг] сервер «weather» → get_weather({"city":"Novosibirsk"})
    → температура 19°C, ветер 9 км/ч, Clear
[шаг 2 · роутинг] сервер «knowledge» → search({"query":"Новосибирск"})
    → Новосибирск — город в России, административный центр Новосибирской области…
[шаг 3 · роутинг] сервер «knowledge» → summarize({"text":"…"})
    → Новосибирск — третий по величине город России, центр Сибири…
[шаг 4 · роутинг] сервер «files» → save_to_file({"content":"…","filename":"day20_novosibirsk.txt"})
    → Сохранено: …\day20_novosibirsk.txt (… байт)

=== ФИНАЛЬНЫЙ ОТВЕТ АГЕНТА (шаг 5) ===
Готово: собрал погоду и справку, сделал сводку и сохранил в файл.
```

Видно весь смысл задания: агент сам выбрал инструменты, КАЖДЫЙ ВЫЗОВ маршрутизируется на свой
сервер («weather», «knowledge», «files»), порядок логичный, флоу длинный — несколько шагов.

## ШАГ 2 (опционально) — другая цель
```
.\gradlew.bat :week4:day5:run --args="Узнай погоду в Berlin и справку о Берлине, сделай сводку и сохрани в berlin.txt" --console=plain -q
```
→ та же оркестрация для другого города (модель сама перестроит вызовы).

---

**Заметки для съёмки:**
- Прогони один раз заранее (зависимости + первый прогон), чтобы в кадре не было лога загрузки.
- DEEPSEEK_API_KEY уже в корневом .env.
- Порядок/аргументы вызовов выбирает модель — от прогона к прогону могут чуть отличаться, это норма для LLM-оркестрации.

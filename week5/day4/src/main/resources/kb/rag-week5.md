# Неделя 5 — RAG

## Идея

Retrieval-Augmented Generation — подкачка внешних знаний в LLM во время инференса. Вопрос → поиск релевантных чанков в нашей базе → объединение с вопросом → запрос к LLM → ответ, опирающийся на конкретные документы. Отличие от промпт-инжиниринга: не всё запихиваем в системный промпт, а достаём по запросу. Отличие от MCP: MCP — внешние инструменты, RAG — внутренние знания.

## День 21 (week5/day1) — стратегии чанкинга

Реализованы два способа чанкинга:

- **FixedSizeChunker** — фиксированное окно (например, 500 символов) с overlap (100 символов).
- **StructuralChunker** — по секциям Markdown (`##` заголовки).

Оба сохраняют чанки в SQLite (`org.xerial:sqlite-jdbc:3.46.1.3`), эмбеддинги — учебный `BagOfWordsEmbedder` (256-мерный вектор). Косинусная мера для поиска. Метрики: **Recall@3** (доля вопросов, где нужный источник в топ-3) и **MRR** (Mean Reciprocal Rank).

Корпус на дне 21 — общий (языки программирования, планеты, музыкальные инструменты, географические факты).

## День 22 (week5/day2) — первый RAG-запрос

Задача: агент в двух режимах — **с RAG** и **без RAG** — и сравнение качества на 10 контрольных вопросах.

Стек дня 22:

- **Эмбеддинги:** локальный Ollama, модель `nomic-embed-text` (768-мерный вектор). API `http://localhost:11434/api/embeddings`, без ключей.
- **LLM:** DeepSeek `deepseek-chat` через `https://api.deepseek.com/chat/completions`.
- **Хранилище чанков:** in-memory `List<Chunk>` (для 50-100 чанков достаточно, без Chroma/FAISS).
- **База знаний:** 10 MD-файлов «Вики нашего челленджа» в `src/main/resources/kb/`.
- **Ретривер:** cosine similarity, top-3.

Метрики:

- **Retrieval@3** — попал ли ожидаемый источник в топ-3 чанков.
- **Grounded answer** — есть ли ключевые слова из ожидаемого ответа в реальном ответе LLM.

## Отличие от классических RAG-фреймворков

Мы не используем LangChain, LlamaIndex или Haystack. Всё пишем руками на Kotlin — так лучше видно механику: чанк → эмбеддинг → вектор → cosine → top-k → промпт с контекстом → LLM.

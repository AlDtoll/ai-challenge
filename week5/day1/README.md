# Day 21 — RAG индексация: fixed vs structural chunking

Первый день недели RAG. Строим локальный индекс над 25 синтетическими источниками, сравниваем две стратегии чанкинга.

## Что реализовано

- **Corpus**: 25 синтетических Markdown-документов в `src/main/resources/data/` на разные темы (напитки, языки программирования, фронтенд-фреймворки, музыкальные инструменты, планеты, географические объекты). Суммарный объём — 89 KB текста ≈ 36 страниц (при 2500 симв./стр.), с запасом над требованием задания «20-30 страниц».
- **Chunker'ы (2 стратегии)**:
  - `FixedSizeChunker` — режет каждый документ на куски по 600 символов с overlap 100.
  - `StructuralChunker` — режет по Markdown-заголовкам (H1/H2/H3): один заголовок → одна секция → один чанк.
- **Метаданные** (в каждом чанке): `source` (имя файла), `title` (H1 документа), `section` (заголовок раздела для structural, `null` для fixed), `chunkId` (стабильный, вида `python.md#s-2`), `strategy` (`fixed` | `structural`).
- **Embedder**: локальная заглушка bag-of-words (256-мерные векторы, нормализованные), без сети. Интерфейс `Embedder` вынесен — в следующих днях легко заменить на реальный OpenRouter / Ollama.
- **Хранилище**: SQLite (`day21_index.db`), одна таблица `chunks`, обе стратегии живут вместе, различаются полем `strategy`. Векторы хранятся как BLOB (Float32 в little-endian).
- **Оценка**: 25 тестовых вопросов, для каждого известен «правильный» файл-источник. Метрики:
  - **Recall@3** — доля вопросов, где правильный источник попал в топ-3.
  - **MRR** — Mean Reciprocal Rank.
- **Отчёт**: `day21_comparison.md` генерируется автоматически, содержит сводные метрики + разбор каждого вопроса (какой файл вернула каждая стратегия в top-1).

## Запуск

Windows:

```powershell
chcp 65001
.\gradlew.bat :week5:day1:run --console=plain -q
```

Linux/macOS:

```bash
./gradlew :week5:day1:run --console=plain -q
```

С параметрами (по умолчанию `both`):

```powershell
.\gradlew.bat :week5:day1:run --console=plain -q --args="--strategy both --out day21_index.db --report day21_comparison.md"
```

Параметры CLI:
- `--strategy fixed|structural|both` (по умолчанию `both`).
- `--out <path>` — путь к SQLite-файлу индекса (по умолчанию `day21_index.db`).
- `--report <path>` — путь к Markdown-отчёту сравнения (по умолчанию `day21_comparison.md`).

## Ожидаемый вывод

Программа печатает:
1. Статистику корпуса (сколько файлов, символов, страниц).
2. Список тестовых вопросов.
3. Для каждой стратегии — количество чанков, среднюю длину, время индексации, Recall@3, MRR.
4. Итоговое сравнение по вопросам (для каждого — какой файл вернула fixed / structural в top-1).

После завершения:
- `day21_index.db` — SQLite с чанками обеих стратегий.
- `day21_comparison.md` — Markdown-отчёт со сводными таблицами.

## Особенности реализации

- **Embedder на заглушке** — сознательное упрощение дня 21 для отработки пайплайна. Bag-of-words работает по совпадению слов (не по смыслу): «кофе» и «капучино» для него разные. Реальный embedder подключим в следующих днях недели, интерфейс уже готов.
- **Одна таблица под обе стратегии** — упрощает сравнение и переиспользование индекса в последующих днях (retrieval, re-ranking).
- **StructuralChunker для Markdown** — рассекает по H1/H2/H3, section в метаданных содержит текст заголовка. Для чистых лонгридов без заголовков стратегия вырождается в один чанк на файл (ожидаемое поведение).

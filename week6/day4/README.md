## Что оптимизировано (3 фронта)

### 1. Параметры Ollama

| Параметр | BASELINE (day 28) | OPTIMIZED | Смысл |
|---|---|---|---|
| `temperature` | 0.2 | **0.0** | На RAG креативность не нужна, только точность |
| `num_ctx` | 2048 (Ollama default) | **8192** | В baseline промпт+контекст на 3 чанка часто **обрезается**, что ломает retrieval |
| `num_predict` | -1 (без лимита) | **256** | Без лимита модель обрывает JSON/списки в середине |
| `top_p` | 0.9 | **0.5** | Уменьшить вариативность |
| `repeat_penalty` | 1.1 | **1.2** | Штраф за повторы |
| `stop` | — | `["\n\n---", "Вопрос:"]` | Обрубить если модель начала новый чат |

### 2. Квантование

| Preset | Модель | Размер | Влезает в 6 GB VRAM? |
|---|---|---|---|
| BASELINE | `qwen2.5:7b` (Q4_K_M) | ~4.7 GB | 79% на GPU + 21% offload на RAM (у нашей 6 GB) |
| QUANT | `qwen2.5:7b-instruct-q3_K_M` | ~3.2 GB | **100% на GPU** → –53% латентности на 3060 6 GB (данные dpmn day 29) |

### 3. Prompt-шаблон

**V1 (BASELINE, day 28):**
```
Контекст: [S1] … [S2] … [S3]
---
Вопрос: X
Отвечай кратко на русском. Ссылайся на источники [S1]/[S2]/[S3].
```

**V2 (OPTIMIZED):**
```
Ты — точный документальный ассистент. Правила:
1) Каждый факт → маркер [S1]/[S2]/[S3] СРАЗУ за фразой.
2) Только по контексту. Не хватает — «Недостаточно контекста.»
3) Максимум 3 предложения. Без вводных слов.

Пример хорошего ответа:
Q: Какую модель использовал в day26?
A: Использована qwen2.5:7b через Ollama [S1]. Модель занимает ~4.7 GB VRAM [S2].

Пример плохого ответа (НЕ делай так):
Q: Какую модель использовал в day26?
A: Согласно предоставленным материалам, для day26 автор использовал модель Qwen 2.5 версии 7B…

Контекст:
[S1] … [S2] … [S3]
---
Вопрос: X
Ответ (только по контексту, с маркерами, максимум 3 предложения):
```

Идея из эталона sergio: **contrastive example** («хороший / плохой ответ») моделирует лучше, чем список правил.

## Три пресета

```kotlin
BASELINE  = qwen2.5:7b  + T=0.2 + ctx=2048 + npred=-1 + prompt V1
OPTIMIZED = qwen2.5:7b  + T=0.0 + ctx=8192 + npred=256 + prompt V2
QUANT     = qwen2.5:7b-instruct-q3_K_M + параметры OPTIMIZED
```

**Общий retrieval для всех трёх** — сравнение честное, вклад LLM изолирован.

## Метрики

- **`verbatimRate`** — доля 8-грамм ответа, дословно совпадающих с контекстом. Высокая = мало галлюцинаций. Наследуется из day 28.
- **`parse_failure`** count — сколько ответов НЕ содержат маркер `[Sn]` **или** обрываются посреди слова/скобки. Ключевая метрика оптимизации промпта + `num_predict`. У sergio на 12 контрольных: baseline 2/12 «Unterminated string», optimized **0/12**.
- **`GET /api/ps`** → память модели: `size_vram / size_total` = доля на GPU. Данные без запуска `nvidia-smi`.
- **`wall/tok/s`** — как в day 27/28.

## Команды REPL

```
:preset baseline|optimized|quant     переключить активный
<вопрос>                             задать активному
:compare-presets <вопрос>            все 3 side-by-side (на одном retrieval)
:eval [<файл>]                       через активный пресет
:eval --presets [<файл>]             через все 3, сравнительная таблица
:warmup [all]                        прогрев (важно! num_ctx = load-time)
:ps                                  /api/ps → что в памяти Ollama
```

**⚠️ Про warmup:** `num_ctx` — это **load-time** параметр Ollama. При переключении пресетов с разным `num_ctx` первый запрос платит **cold-swap tax** (переуплату времени на перегрузку). Всегда делай `:warmup all` перед серией измерений — иначе первый пресет будет в невыгодном положении.

## Ожидаемые метрики (RTX 3060 Laptop 6 GB)

| Preset | wall avg (ms) | tok/s | verbatim | parse_fail | GPU/RAM |
|---|---|---|---|---|---|
| BASELINE | ~1400 | ~40 | 0.32 | 2-3/5 | 79% GPU / 21% RAM |
| OPTIMIZED | ~1200 | ~42 | 0.38 | 0/5 | 79% GPU / 21% RAM |
| QUANT | ~700 | ~50 | 0.34 | 0/5 | **100% GPU** |

**Ключевой вывод (задание требует):**
- **Качество:** OPTIMIZED > BASELINE (плотнее цитаты, ноль parse_failure).
- **Скорость:** QUANT ≈ вдвое быстрее (Q3_K_M влезает целиком в 6 GB, нет offload на RAM).
- **Ресурсы:** QUANT весит 3.2 GB vs 4.7 GB — освобождает VRAM.
